# 知识体系运行契约

## 最小组成

一套可持续运行的知识体系至少包含：

1. 根 `AGENTS.md`：项目目标、读取顺序、隐私边界、用户控制和通用维护规则；
2. 根 `index.md`：知识体系地图、一级分区、关键关系和当前入口；
3. 每个独立知识分区的 `AGENTS.md` 与 `index.md`；
4. 待处理机制和历史知识的保留方式；
5. 必要的来源、状态、版本和关系表达；
6. `.knowledge-system.json`：供确定性检查使用的轻量运行清单；
7. 首次验证记录，其中包含经用户确认的知识对象覆盖映射。

纯附件、图片、缓存、依赖、构建产物和机械叶子目录不重复生成规则或索引。

## 根入口

根 `AGENTS.md` 应规定：

- 执行重要任务前先读取根 `index.md`；
- 确定目标分区后读取其规则、索引和必要正文；
- 默认按需读取，不通读全库；
- 区分事实、来源证据、用户判断、AI 推断和待确认信息；
- 新信息、影响分析、结构变化、归档和删除的全局边界；
- 用户对分类、结论、确认范围和删除拥有最终决定权。

根 `index.md` 只做项目级导航和关键状态说明，不展开全部文件。索引只在知识对象、状态、关系或入口变化时更新，不因普通措辞和格式修改而更新。

## 分区入口

分区 `AGENTS.md` 只写该分区特有的：

- 职责、准入和排除；
- 上游、下游和关键关系；
- 查询、新增、修改和冲突处理；
- 来源、状态、版本、替代和归档规则；
- 索引更新条件；
- 无法判断时的去向。

分区 `index.md` 记录当前内容、状态、来源和必要关系，优先使用短表格与单句摘要。通用规则继承根层，不在每个分区重复。

## 最小关系语义

根据场景使用自然语言链接、frontmatter、索引表或文档关系区块表达：

| 关系 | 含义 | 维护用途 |
|---|---|---|
| 来源于 | 当前内容来自某项输入或记录 | 追溯依据，不反向改写来源 |
| 支持 | 证据支持某个判断 | 证据变化时复核判断 |
| 反驳 | 证据挑战某个判断 | 新反证进入时触发复核 |
| 派生自 | 下游内容由上游判断或方案形成 | 上游变化时检查下游 |
| 呈现或实现 | 某项内容表达或落实了方案 | 方案变化时检查表达与实现 |
| 替代 | 后续版本或结论取代原内容 | 区分当前有效与历史 |
| 相关 | 有参考价值但没有确定依赖 | 默认不传播修改范围 |

只记录对检索、追溯和变化维护有用的关系。确定依赖与普通相关必须能够区分；缺失关系不得补造。

## 状态和历史

状态名称应少而清晰，并能区分当前有效、待确认、进行中、已暂停、已替代和已归档。旧内容具有决策、审计或复盘价值时，通过替代关系或归档保留；当前入口只指向当前有效内容。

元数据按任务需要使用，不要求每份旧文档批量补齐。新建正式知识通常至少记录标题、知识类型、状态、更新时间；存在外部或原始输入时再记录来源。

## 运行清单

文件生成后运行：

```text
python3 scripts/runtime_tool.py manifest \
  --project <项目绝对路径> \
  --section <一级分区相对路径> \
  --generated-file <其它生成文件相对路径> \
  --validation-file <首次验证记录相对路径> \
  --status <building|incomplete|complete> \
  --pretty
```

`complete` 必须有通过的首次验证记录。运行清单记录规则文件生成时的指纹；规则后来发生变化只触发复核提示，不得自动覆盖用户维护内容。运行清单不进入普通知识查询上下文，也不承担业务语义判断。
