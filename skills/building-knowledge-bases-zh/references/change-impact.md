# 变化影响与联动维护

## 触发条件

以下情况先做影响分析：

- 事实被纠正；
- 判断、需求、方案、定位或决策发生变化；
- 当前内容被另一版本或结论替代；
- 用户询问哪些内容需要一起调整；
- 新增信息与当前有效内容冲突。

普通排版、错别字、格式和不改变结论的文字优化不触发全库分析。

## 分析方法

1. 明确变更源、新旧差异和依据。
2. 找到其来源与上游证据，确认变化是否成立。
3. 查找直接引用、支持、反驳、派生、呈现、实现或替代该对象的内容。
4. 沿确定依赖检查必要的间接影响；普通相关默认不传播。
5. 对照当前状态、分区规则和历史版本。
6. 标记必须修改、需要复核、保留历史和明确不受影响的内容。
7. 记录关系缺失、来源不足和需要用户判断的事项。

影响分析不能只返回关键词命中文件；每个结果必须说明关系与原因。

## 影响清单

写入前使用稳定 ID 列出：

| 字段 | 要求 |
|---|---|
| ID | 在本轮确认和执行中保持稳定 |
| 变更源 | 新旧差异及依据 |
| 文件或知识对象 | 指向具体内容 |
| 影响层级 | 必须修改、需要复核、保留历史或不受影响 |
| 关系类型 | 来源、支持、反驳、派生、呈现、实现、替代或其它 |
| 影响原因 | 说明为什么受到影响 |
| 建议动作 | 修改、补充、标记历史、复核或不处理 |
| 不确定项 | 缺失信息和需要用户判断的内容 |

用户可以按整组、分区或具体 ID 确认。未确认前不得执行会改变多份文档结论、状态或归属的修改；只确认部分时只执行该部分。执行范围出现新增文件或不同动作时，重新说明并确认。永久删除唯一原件始终单独确认。

## 联动修改

确认后按以下顺序执行：

1. 保存新的来源或变更依据；
2. 更新变更源和当前判断；
3. 更新直接依赖的方案和下游交付物；
4. 更新状态、版本、替代和历史关系；
5. 更新索引与链接；
6. 检查当前有效内容是否仍有明显冲突；
7. 报告已修改、未修改、失败和待确认事项。

找不到来源时标记来源缺失；多条证据冲突时保留冲突并请求判断；关系不足时列为待复核，不强行扩大范围；文件无法安全修改时保留引用并报告限制。任何失败都不得通过近似动作绕过用户确认。
